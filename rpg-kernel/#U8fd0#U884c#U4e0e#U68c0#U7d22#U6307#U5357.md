# 运行与检索指南

两部分：**怎么跑起来** 和 **搜索怎么配、怎么用**。

---

## 一、怎么跑

**Windows：双击 `一键启动.bat`。** 它会自己找 Node、起服务、3 秒后自动开浏览器，窗口保持开着显示日志；关窗口或按 Ctrl+C 即停。

它按这个顺序找 Node：系统 PATH 里的 `node` → WorkBuddy 自带的托管版本 → Program Files 下的标准安装 → nvm 目录。都没找到会提示去 nodejs.org 装 22 LTS。端口被占用时会告警并提示换端口，不会盲启一个崩掉的实例。

手动启动（macOS / Linux / 想自定义端口）：

```bash
node server.js                 # 默认 8787
PORT=8899 node server.js       # 换端口
```

Node 22 以上，零依赖，`npm install` 都不用跑。

> bat 窗口里的状态行故意写成英文：Windows 控制台默认还是本地代码页（936/950），UTF-8 中文 echo 出来是乱码。浏览器里的界面是全中文的，不受影响。

### 第一次使用的五步

1. 双击 `一键启动.bat`，浏览器自动打开并选中「DeepSeek」。
2. 「框架配置」粘贴你的 DeepSeek API Key →「连通测试」看到 `OK` 为止。
3. 「检索配置」选 Wikidata（查重名最好用，免费无需 key）→「试搜」验证。
4. 顶部选存档（已内置两个示例局面：叶知微 / 严俊），或「新建存档」从规则包开局。
5. 底部输入你的行动，需要触及哪条线索就 Ctrl 多选哪条，**不选就等于禁止 GM 替你推进线索**；「推进回合」→ 看右栏审查 → 确认没问题点「采纳并推进」。

**填过一次就不用再填**：Key 存在 `data/adapter-config.json`，重启、换浏览器、清缓存都还在。以后双击就能直接开局。

**不配任何 Key 也能用**：叙事适配器选「本地骨架」，整套管线会跑通但不产生正文；检索后端选 Wikipedia/Wikidata，检索照常工作。

### 改端口

```bash
PORT=8899 node server.js
```

## 二、搜索怎么配

### 三条免费路线（不用注册、不用 key）

| 后端 | 适合查什么 | 短板 |
|---|---|---|
| **Wikipedia**（默认） | 地名沿革、知名人物的生卒年与官职 | 中文条目简略，中下层人物大量缺失 |
| **Wikidata** | **查重名最有效** —— 里面的中国历史人物大多来自 CBDB（中国历代人物传记资料库），包括很多《宋史》《唐书》里只有一行字的人 | 只有结构化元数据，没有叙述 |
| **SearXNG** | 想免费拿全文搜索引擎的结果 | 要自己部署一个实例，并开启 JSON 输出 |

**推荐组合：叙事用一个带 key 的模型，核查默认就用 Wikidata。** 查重名这块它比通用搜索准得多。

### 需要 key 的四条付费路线

| 后端 | 去哪拿 | 大约成本 | 什么时候用 |
|---|---|---|---|
| **博查 bochaai.com** | bochaai.com 注册 | 极便宜，按次几分钱 | **做中国史优先选它**，中文语境和国内站点覆盖最好 |
| **Tavily** | tavily.com 注册，有免费额度 | 有免费额度 | 返回的就是干净摘要，最省事 |
| **Serper.dev** | serper.dev，Google 结果 | 有免费额度 | 需要 Google 索引、找地方志类冷门站点 |
| **Bing / Azure** | Azure 门户建 Cognitive Services | 免费层每月有额度 | 要最稳定的商业 SLA |

配置方式：控制台「设置」→「检索后端」→ 选后端 → 填 Key → 点**「测试检索」**验证 → 确定。配置存在 `data/search.json`。注意叙事适配器的 Key 和检索的 Key 是两套独立配置，别串台。

### 博查（bocha）接不通的排查

博查有个**很容易踩的坑**：它的 key 无效或额度用尽时，**HTTP 状态码可能仍是 200**，真正的错误藏在响应体里：

```json
{"message":"Invalid API KEY","log_id":"...","code":"401"}
```

如果只看 HTTP 状态，就会误判成"连上了但没结果"。本引擎的博查适配器**已经检查 `body.code`**，会把真实原因报出来（如「API Key 无效或未生效，请到博查控制台核对」）。

排查步骤：

1. 设置 →「检索后端」选**博查** → 确认 Key 是 `sk-` 开头、无多余空格；
2. 点**「测试检索」**。成功会显示「成功：N 条，XXXXms」并给一条示例结果标题；
3. 若提示 Key 无效：到 bochaai.com 控制台确认 **Key 已启用、余额未耗尽、未绑定域名限制**；
4. 若显示「连上了但没返回结果」：多半是 `count` 填了非法值，或该查询确实无结果，换个词再试；
5. **常见误操作**：以前版本打开「设置」后检索源下拉框会默认停在第一项（维基百科），一点确定就把你的博查**悄悄改回**了。现已修复——下拉框会回填成你当前在用的源。若你用的是旧版，请重开设置确认选中项是「博查 AI 搜索」再点确定。

另外：`data/search.json` 里 `count` 建议填数字（如 `5`），代码会做 `Number()` 转换，填字符串也能用。

### 不想用 / 断网

选「关闭检索」。此时界面每一条史实类结论都会明确标成「信息缺口」，**不会假装查过**。至少你知道自己当前是裸奔的——伪装的核查比没有核查更害人。

## 三、接 DeepSeek（默认选中的就是它）

控制台下拉第一项「DeepSeek」是已经预置好的，不用手写 URL。两个模型任选：

| Model | 什么时候用 |
|---|---|
| `deepseek-chat` | **默认**。V3，快，适合写正文场景。日常跑这个。 |
| `deepseek-reasoner` | R1，慢很多但推理强。适合当「第二个裁判」做核查——把 `python-subprocess` 或 `http-json` 再注册一份指向它，生成用 V3、核查用 R1。 |

几个已经处理好的细节：

- **R1 不接受 `temperature`**，传了会报错。引擎按模型名自动跳过采样参数，你切 `deepseek-reasoner` 不用改别的地方。
- Key 存在 `data/adapter-config.json`（**纯本地**，不上传任何地方）。
- 我用无效 key 实测过：DeepSeek 返回它自己的 `401 authentication_error`，说明端点、协议、鉴权头全对——填上真 key 就能跑。

想换别的厂商，下拉里的「OpenAI 兼容接口」覆盖 DeepSeek / Qwen / Moonshot / vLLM / LM Studio，改 Base URL 和 Key 即可。

## 四、搜索在游戏里怎么被调用

不是"想到才搜"，而是按你 v3.3 那套**四层核查**埋进流程：

| 你的层级 | 界面入口 | 引擎实际做什么 |
|---|---|---|
| 第 0 层 场景宏观（地名/控制者） | 右栏「核查当前地点」 | 查 `<地点> <政权> <年号> 治所沿革`、`<地点> <年号> 建置` 两条 |
| 第 1 层 真实人物（生卒年/官职） | 「核查措辞」旁人物核查接口 | 先精确短语 `"<姓名>"`，再查 `<姓名> 生卒年 字号 籍贯`、`<姓名> <年号> 官职 事迹 传` |
| 第 1 层 虚构 NPC（五步验证） | 草稿区每个新人物旁的「核名」按钮，或勾选「本回合自动核对新人物重名」 | 走完整五步：确定名字 → 双源检索 → 判定 → 列出待补三项 → 给出登记表模板 |
| 第 3 层 措辞是否属于该时代 | 右栏「核查措辞」 | 查 `"<词>" 出处 最早见于 <年号>` |

每次核查都在「事实核查记录」里留档，附**可点击的原始链接**，你自己判定，引擎不下结论。

### 实测效果（真跑出来的，不是演示数据）

| 候选项 | 结果 |
|---|---|
| 虚构「钱乙」（常州押司） | **抓到**。维基标题命中「钱乙」条目——那是宋代名医钱乙。《小儿药证直诀》的作者。直接劝退改名。 |
| 虚构「郑巽」 | **抓到**。Wikidata 直接检得 5 个实体，含多个 CBDB 唐代人物。 |
| 虚构「林月娥」 | **抓到**。Wikidata 有同名真实实体 Q98096275。 |
| 虚构「慕容雪见」 | 未见同名。注意这只是"有名可查的那批里没撞"。 |

## 五、判定标准：为什么它从不说「通过」

核查结果只有三态，与正文审查器的口径一致：

- **存疑** → 拿到了疑似证据，**例如上面表格里的钱乙**。你自己点开链接确认，引擎绝不替你拍板改名或不改。
- **未见同名** → 当前源里没找到。**但报告里会明说：搜不到 ≠ 不存在。** 乡里小人物不会被任何搜索引擎收录，这里只能保证"不是有名可查的那批人"。
- **信息缺口** → 检索失败 / 未启用了 / 返回条目经相关性过滤后一条不剩。**这种情况下你不要假设名字可用。**

相关性过滤是硬性的：如果返回的条目在标题和摘要层都不含被核查的那个词，直接剔除并如实告诉你剔了多少条。宁可报缺口，也不拿不相干的条目冒充证据。

浏览器部分这套东西只能做**候选挖掘**，不能做**终审**。终审人是你。

## 五之二、纳米级剧情审计（P0–P9 十遍扫描）

侧栏「纳米审计」页。每轮把输出拆成**断言、动作、对话行、数字、状态**这些原子，十遍扫：

| 遍 | 查什么 | 典型报错 |
|---|---|---|
| P0 | 输入对账：把你的话拆成约束（明确/未明确/必须兑现/禁止越界）、模糊指令、优先级、授权台账 | 你没授权却越界 |
| P1 | 主语归属：主角句分 A–F 六类 | D01 你打定主意（S0）／D02 你心想（S1）／C01 你随即…（S1）／C02 动作无出处（S2）／S01 他替你应下（S0）／S02 替你说整段话（S0） |
| P2 | 断言核查：身份、年龄、人物官职与状态卡比对 | A01 身份冲突／A02 年龄冲突／A03 人物官职冲突／A04 据传类托词 |
| P3 | 时间线：倒流、跨日、与时钟不符、路程与时长不符 | T01–T04 |
| P4 | 在场表：凭空出现、退场后还在、已故者出场 | P01／P02／P03（S0） |
| P5 | 四本账：人情、利害、信息、物资 | L01 无底账／L02 没有代价的顺利 |
| P6 | 知识矩阵：谁知道什么 | K01 未卜先知（S0）／K02 信息无出处／K03 旁人知道无目击者的事 |
| P7 | 对话审计：说话人、身份、语域、台词长度 | G01 现代说法／G02 说话人不在表／G03 没标说话人／G04 台词过长 |
| P8 | 情节节拍：新信息／转折／代价／选择点／新人物 | B01 几乎没推进／B02 没交还选择权 |
| P9 | 状态卡与追溯：状态卡差异、**复发（回归）判定** | R01 已修错误复发 |

- **严重度**：S0 致命（与必过项同级，命中即整轮作废）／S1 严重／S2 一般／S3 提示。
- **证据等级**：E0 凭空、E1 模型自述、E2 档案可查、E3 检索证据。每条都标出来，方便你判断该不该信这条报错。
- **六类主角句**（P1 的核心）：A 感官、B 身体、E 被动结果、F 状态陈述——**允许**；C 外在动作——**须有玩家出处，或属最小细化**（点头、拱手、起身）；D 内心——**禁写**，除非玩家本轮写了或明确授权。
- **回归**：每个错误码都进 `state.passHistory`。某一类错误上一轮没了、这一轮又出现，P9 会标「已修错误复发」。
- 这些规则同时写进了提示词（「十遍扫描防线」八条），先防后查，不是只做事后挑错。

## 五之三、世界运行六模块（世界不是一个背景板）

P0–P9 管的是「这一轮的文字写得对不对」。下面六个模块管的是「这个世界跑起来对不对」。

| 模块 | 文件 | 干什么 |
|---|---|---|
| 世界状态机 | `core/world.js` | 24 项结构化状态（时间/地理/政治/人口/财政/军事/交通/气候/法律/情报…），每轮自行推进：季节、天气、交通、疫病、宏观三层、社会秩序 |
| 资源与经济 | `core/economy.js` | 按城邑规模（都城/州府/县/镇/乡/村）建户数与人口，推出丁男丁女、职业结构、田亩与岁入；四本账（人员/财政/军事/关系）**每笔必须带来源**，无来源即 NU-02 |
| 信息传播 | `core/info.js` | 事实分 F1 已确认 / F2 高概率 / F3 推测 / F4 虚构 / F5 未知；谁知道了什么、怎么知道的（亲眼/耳闻/文书）；过若干日会生出「传闻」，真值未知 |
| NPC 自主 | `core/npcAgency.js` | 每个 NPC 有目标、恐惧、底线、行动能力、亲疏；玩家不来找他们，他们也在排队做事（催收、议亲、囤积、上告、串供、打点退路…）。玩家提要求时按 `得分 = 好处×0.9 + 亲疏×0.5 + 行动能力×0.2 − 代价×0.8 − 风险×(1.2−风险承受)×1.4` 决定十种反应之一，**可以拒绝** |
| 历史分歧 | `core/divergence.js` | 硬锚点不可推翻；影响半径七级（一人→朝廷）；事件规模六级；因果链须登记「因→果 + 延迟 + 中间经过谁」；反事实检验（删除测试 / 替换测试）；偏离按半径一级一级往外传 |
| 快照回滚 | `core/snapshot.js` | 每 5 轮及重大事件后存完整快照；发现错误先定位**最早**那一次（不是最近一次），列出从那时起被污染的状态项，回滚到干净起点重跑 |

侧栏新增两页：**「世界」**（24 项状态、人力钱粮兵、人物各自在做什么、谁知道什么、锚点与因果、本轮世界自己发生了什么）、**「回滚」**（最早错误、建议回滚点、快照列表、被污染项查询）。

## 五之四、世界扫描 P10–P15

与 P0–P9 同一套严重度（S0 命中即整轮作废）与展示方式，显示在「纳米审计」页底部。

| 遍 | 查什么 | 错误码 |
|---|---|---|
| P10 历史真实性 | 硬锚点是否被推翻、真实人物是否做了史无记载的大事、用词是否时代错置 | HT-01（S0）／HT-02／HT-03 |
| P11 资源守恒 | 四本账每笔有没有来源；正文冒出来的「五千兵」「三千民夫」是否超出本地承载力 | NU-01 超限／NU-02 无来源／NU-03 兵力／NU-04 钱粮 |
| P12 信息泄漏 | NPC 是否说了他不可能知道的事；F5 未知是否被写成确凿事实 | IN-01（S0）／IN-02 |
| P13 NPC 自主性 | 他凭什么无条件答应？有没有登记自己的目标与恐惧 | NPC-02／NPC-03 |
| P14 因果传播 | 无因之果、影响半径越级、规模不守恒、朝廷级后果无传递路径、重大后果零延迟 | CA-01…CA-05 |
| P15 回归 | 旧错复发、已纠正项再现、死人复生、缺快照无法回滚 | RV-01…RV-04 |

自查办法：把适配器选成 **「本地假文（离线自检审计用）」**，它会返回一段故意埋了错的固定正文，不用 API Key 也能验证各遍是不是真的会拦。埋的雷包括：替玩家决定、替玩家说话、无来源的账、NPC 无条件答应、推翻锚点、时代错置、数量超承载力、重大后果零延迟。

## 六、成本与缓存

- 检索结果缓存在 `data/cache/`，同名查询不再重复扣次数。想强制重查就在一次请求里带 `noCache`（界面「试搜」默认不走缓存）。
- 免费源做了退避重试，遇到 429/503 会自己 retry 两次。
- 一个回合开「自动核对」会有 N 个新人物 × 3 次查询，加上一批新名查询。用付费源时心里有数；日常釣 WIKIDATA 免费就够。

## 七、排错

| 现象 | 原因 / 处理 |
|---|---|
| 双击 bat 报找不到 Node | 去 nodejs.org 装 22 LTS（安装时勾 Add to PATH），重双击 |
| bat 说端口被占用 | 改端口运行 `PORT=8899 node server.js`，或先关掉另一个实例 |
| 「连通测试」报 `401 authentication_error` | **链路是通的**，只是 Key 不对或没充钱。去 DeepSeek 控制台确认 key 有效、有余额 |
| 试搜报 `HTTP 403/429` | 公开 API 限流，等几十秒再试；或换 Wikidata |
| 一切结论都是「信息缺口」 | 检索后端选了「关闭」，或源没有配 Key |
| `connect ECONNREFUSED` 到 SearXNG | 实例没起，或实例没开 JSON 输出（要 `{实例}/search?format=json`） |
| 网页能开但「推进回合」报未配置 | 叙事适配器与检索后端是两套独立配置，别搞混：叙事填 DeepSeek，检索选 Wikidata |
| 报告很长看不过来 | 审查面板每条都加了折叠的「证据来源」，点开才显示链接 |
| 「连通测试」报 `ECONNREFUSED` / 超时 | 本机网络或代理挡了。检查能否访问 api.deepseek.com |
