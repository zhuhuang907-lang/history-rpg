# 端点（API）审查报告 — 2026-10-08

> 范围：`server.js` 暴露的全部 HTTP 路由，以及它们调用的 `core/engine.js` 函数。
> 审查方法：逐路由静态走读 + 关键路径（文件读写）的单元测试（`selftest_endpoint_security.js`）。
> 说明：本次**未**改动经济（`economy.js`）逻辑，仅聚焦 API 端口的正确性、安全性与健壮性。

---

## 一、重大缺陷（已修复）

### 1. 路径穿越（Path Traversal）—— `loadState / deleteSave / writeState / createSave`
- **现象**：存档 id 直接拼进文件路径：`path.join(SAVE_DIR, \`${id}.json\`)`，**没有任何过滤**。
- **后果**：
  - `POST /api/save/delete` 传入 `saveId:"../../SEC_PROBE"` 可删除 `data/saves` **之外**的 `.json` 文件；
  - `POST /api/state`、`POST /api/world/update` 等可读取/覆盖目录外的文件；
  - 静态文件服务（`serveStatic`）早就有穿越防护（白名单 + `startsWith(PUBLIC)` 校验），**但 API 端口缺了这一层**，形成不一致。
- **`saveId` 缺失更隐蔽**：`deleteSave(undefined)` 会拼成 `data/saves/undefined.json`，文件不存在时旧代码静默返回 `{ok:true}`，前端以为删掉了、其实什么都没发生——这正是「点了删除什么都没反应」的根因之一。
- **修复**：新增 `safeId(id)` 白名单校验（拦截 `/` `\` `..` 及空值/控制字符；放行字母数字 `_ -` 与中文），并在上述四个函数入口调用。非法 id 一律抛 `BADID`；`loadState` 对缺失文件改为抛出明确的「存档不存在」而非裸 `ENOENT`。

### 2. 删除无 id 时的静默「成功」（随 #1 一并修复）
- `/api/save/delete` 现在对 `undefined/空/非法` 返回 `{ok:false, why:"缺少或非法的 saveId…"}`，前端会弹出「删除失败」并给出原因，不再假成功。

## 三、本次修改清单（代码层）

1. `core/engine.js`
   - 新增 `safeId(id)`：白名单校验，拦截 `/ \ ..` 与空值/控制字符；放行字母数字 `_ -` 与中文。
   - `loadState(id)`：先 `safeId`；文件缺失时抛「存档不存在」（code `ENOENT`）。
   - `writeState(s)`：`safeId(s.meta.id)` 再写盘。
   - `createSave`：`safeId(starterId)`。
   - `deleteSave(id)`：`safeId(id)`。
2. `selftest_endpoint_security.js`（新增）：单元测试守住「穿越 id 被拒」「空 id 被拒」「缺失档明确报错」「中文合法 id 仍可用」「HTTP 层删穿越 id 不误删外部文件」。
3. `selftest_cleanup.js` + `test_runner.js`（新增）：跑完所有离线自测后**自动删除测试残留存档**（仅删测试前缀，永不动 `liangmo-`/`custom-` 等真实存档）。

## 四、待用户处理（非代码缺陷）

- **Deepseek API Key 401**：`data/adapter-config.json` 里配置的 Key 返回 `HTTP 401`，导致**所有依赖模型的功能**（`/api/turn` 生成剧情、`/api/figure/generate`、`/api/world/seed`、`/api/verify/*`、以及 `selftest_regress_maxisheng.js` 的联网核定）无法正常工作。引擎已能识别并提示「适配器不可用/Key 失效」，但需要一个**有效的 Key** 才能恢复。这是环境/账号问题，不是代码 bug。
